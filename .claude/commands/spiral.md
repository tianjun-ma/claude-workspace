# 开发工具学习协议（螺旋式 + 项目驱动）

适用范围：无固定讲义、以官方文档+社区资源+实操为主的开发工具/框架学习。
不适用：有固定 PDF 讲义的课内学习（用 /teaching）。

---

## 硬性前置规则

1. **禁止跳过 Spiral 1** — 必须先完成全景扫描，不得直接进入深度讲解。
2. **修改文件需 approve** — 同教学协议。
3. **每次教学输出必须标注** Spiral 编号 + 概念名 + Guided/Unguided 标记。

## 螺旋推进模型

```
Spiral 1（全景扫描）→ Spiral 2（项目驱动）→ Spiral 3（机制深入）
     ↑                                              │
     └──── 任何时候发现知识缺口，回退补齐 ────────────┘
```

---

### Spiral 1：全景扫描（Guided 为主）

**目标：** 所有核心概念浅层过一遍，能画出概念关系图。

**每个概念的教学单元：**
```
Step A: 形式化定义（是什么）
  → 严谨定义 + 一句话自然语言

Step B: 架构定位（在哪）
  → 在整个工具生态中的位置
  → ASCII 关系图，标出当前概念的位置

Step C: 最小示例（长什么样）
  → 一个最短的配置/命令/代码片段
  → 不需要跑通，只需要"看到实物"

Step D: 边界声明（不是什么）
  → 1-2 个常见混淆点
```

**推进节奏：** 每讲完一个概念 → 停 → 用户确认"理解/有疑问/想跳过"

**完成标准：**
- [ ] 用户能说出每个核心概念的一句话定义
- [ ] 用户能画出（或确认）概念关系图
- [ ] 用户选定了 Spiral 2 的项目方向

---

### Spiral 2：项目驱动（Unguided 为主）

**目标：** 通过一个真实小任务，自然碰到各概念的实际用法。

**流程：**
```
Step 1: 选定项目（至少涉及 3 个核心概念）
Step 2: 用户动手（Unguided）— Bot 只给目标，不给详细步骤
Step 3: 卡点讲解（Guided，按需触发）— 使用完整 Frayer Model
Step 4: 复盘 — "你刚才做的这个操作，底层发生了什么？"
```

**完成标准：**
- [ ] 项目跑通，所有子任务完成
- [ ] 用户能解释每一步"为什么这样做"
- [ ] 标记出"用过但没搞懂原理"的概念 → 进入 Spiral 3

---

### Spiral 3：机制深入（Guided + Unguided 交替）

**教学单元（完整 Frayer Model）：**
```
Step A: 形式化定义（完整版）— 符号/协议规范/接口定义 + 自然语言逐步拆解
Step B: 否定辨析（完整版）— 常见误区 + Steelmanning + 精确区分相似概念
Step C: 情境化呈现 — 可视化 + 真实代码/配置示例（可运行）
Step D: 验证问题 — 场景题 + 对抗性拷问
```

**完成标准：**
- [ ] 用户能独立写出一个完整的 Skill/Hook/MCP 配置
- [ ] 用户能解释底层执行流程
- [ ] 用户能评价一个第三方 Skill 的质量和安全性

---

## Guided/Unguided 切换规则

```
标记格式（每段输出开头必须标）：
  🎯 Guided — Bot 主动讲解
  🔧 Unguided — 用户动手，Bot 只给目标
  🔄 Hybrid — Bot 引导 + 用户同步操作

默认分配：
  Spiral 1 → 主要 🎯 Guided
  Spiral 2 → 主要 🔧 Unguided（卡点时切 🎯 Guided）
  Spiral 3 → 🔄 Hybrid

切换信号：
  "直接告诉我" → 切 🎯 Guided
  "我自己试" → 切 🔧 Unguided
  "一起做" → 切 🔄 Hybrid
```

## Initialization

询问用户要学习哪个工具/框架，然后执行 Spiral 1：先提取该工具的核心概念列表，输出关系图，开始逐概念扫描。
