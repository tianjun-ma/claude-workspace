# /diagnose — 协议崩坏诊断

> 用于诊断"Bot 行为偏离预期"的根因。四类失效模式逐一检查。
> 触发词：`/diagnose`、"为什么你没有遵守协议"、"协议崩了"、"这不对吧"

---

## 执行步骤

**Step 1 — 描述偏差**
用一句话说清楚：预期行为 vs 实际行为
```
预期：一次引入一个概念，输出后停等确认
实际：一次输出了 4 个概念 + 大量术语
```

**Step 2 — 逐一排查四类根因**

| 类型 | 判断标准 | 检查方式 |
|------|---------|---------|
| 🔴 用户输入错误 | 用户给了错误/矛盾的指令 | 重读用户原始输入 |
| 🟡 上下文污染 | 对话过长，早期关键指令被稀释 | 检查该指令是否在最近 5 轮内被重申 |
| 🟠 协议漏洞 | 规则存在但表述不够约束（建议 vs 硬性规定） | 读对应协议原文，判断是"应该"还是"必须" |
| 🟢 未读文档 | 协议明确写了规则，Bot 直接忽略 | 对照协议原文逐条检查 |

**Step 3 — 输出诊断报告**

```
[/diagnose 报告]
偏差：[一句话]
根因：[类型] — [具体原因]
修复方案：
  - 立即：[当前对话如何纠正]
  - 系统：[是否需要更新协议/MEMORY.md]
```

**Step 4 — 修复执行**
- 协议漏洞 → 提议修改协议原文，用户 approve 后执行
- 上下文污染 → 重述关键约束，继续执行
- 用户输入错误 → 澄清后重新执行
- 未读文档 → 直接重新执行，标注遵守规则

---

## 典型场景

```
用户："你明明说一次一个概念，怎么一下输出了这么多？"
→ /diagnose → 检查四类 → 输出报告 → 修复

用户："为什么你没有先搜索？"
→ /diagnose → 根因=未读文档（MEMORY.md 有规则）→ 立即执行搜索

用户："这个回答风格不对"
→ /diagnose → 根因=上下文污染 → 重述用户偏好 → 重新回答
```
