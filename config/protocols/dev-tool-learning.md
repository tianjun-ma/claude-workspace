## 螺旋推进模型（Spiral Curriculum）

### 设计原理

基于 Bruner 的螺旋课程理论 + Josh Comeau 的 Guided/Unguided 平衡：
- 核心概念反复遇到，每次增加复杂度
- Guided（Bot 讲解）和 Unguided（用户动手）交替进行
- 不是"学完 A 再学 B"，而是"先浅层 ABCDE → 再深入 A → 再深入 B..."

```
Spiral 1（全景扫描）→ Spiral 2（项目驱动）→ Spiral 3（机制深入）
     ↑                                              │
     └──── 任何时候发现知识缺口，回退补齐 ────────────┘
```

---

### Spiral 1：全景扫描（Guided 为主）

**目标：** 所有核心概念浅层过一遍，能画出概念关系图。

**每个概念的教学单元（替代"逐页"）：**
```
Step A: 形式化定义（是什么）
  → 严谨定义 + 一句话自然语言
  → 对应 Frayer 的"肯定陈述 Step A"

Step B: 架构定位（在哪）
  → 在整个工具生态中的位置
  → ASCII 关系图，标出当前概念的位置
  → 类比到用户已知的概念（如：Skills ≈ 你的 protocols.md）

Step C: 最小示例（长什么样）
  → 一个最短的配置/命令/代码片段
  → 不需要跑通，只需要"看到实物"

Step D: 边界声明（不是什么）
  → 1-2 个常见混淆点
  → 对应 Frayer 的"否定辨析"（简化版，Spiral 3 再展开）
```

**推进节奏：**
- 每讲完一个概念 → 停 → 用户确认"理解/有疑问/想跳过"
- 全部扫描完 → 输出概念关系总图 → 用户确认 → 进入 Spiral 2

**Spiral 1 完成标准：**
- [ ] 用户能说出每个核心概念的一句话定义
- [ ] 用户能画出（或确认）概念关系图
- [ ] 用户选定了 Spiral 2 的项目方向

---

### Spiral 2：项目驱动（Unguided 为主）

**目标：** 通过一个真实小任务，自然碰到各概念的实际用法。

**流程：**
```
Step 1: 选定项目（用户选 or Bot 建议）
  → 项目必须至少涉及 3 个核心概念
  → 例："用 Claude Code 给一个 Python 项目写 CLAUDE.md + 创建一个自定义 Skill + 连一个 MCP Server"

Step 2: 用户动手（Unguided）
  → Bot 只给出任务目标，不给详细步骤
  → 用户自己查文档、试命令

Step 3: 卡点讲解（Guided，按需触发）
  → 用户卡住时，Bot 针对性讲解
  → 使用完整 Frayer Model（Phase 2 四维度）
  → 讲完后回到 Unguided 继续

Step 4: 复盘（每个子任务完成后）
  → "你刚才做的这个操作，底层发生了什么？"
  → 对应 Phase 3 费曼闭环的变体
```

**Spiral 2 完成标准：**
- [ ] 项目跑通，所有子任务完成
- [ ] 用户能解释每一步"为什么这样做"
- [ ] 标记出"用过但没搞懂原理"的概念 → 进入 Spiral 3

---

### Spiral 3：机制深入（Guided + Unguided 交替）

**目标：** 对 Spiral 2 中标记的概念做深度拆解。

**教学单元（完整版，使用 Frayer Model 全部四维度）：**
```
Step A: 形式化定义（完整版）
  → 符号/协议规范/接口定义
  → 自然语言逐步拆解

Step B: 否定辨析（完整版）
  → 常见误区列表
  → Steelmanning（为反向观点提供最强辩护）
  → 与相似概念的精确区分

Step C: 情境化呈现
  → 根据概念类型选可视化（流程图/架构图/时序图）
  → 真实代码/配置示例（可运行）

Step D: 验证问题
  → 场景题 + 对抗性拷问
  → 或：用户写一个自己的 Skill/Hook/MCP 配置
```

**Spiral 3 完成标准：**
- [ ] 用户能独立写出一个完整的 Skill/Hook/MCP 配置
- [ ] 用户能解释底层执行流程（Tool Use → MCP → LLM 调用链）
- [ ] 用户能评价一个第三方 Skill 的质量和安全性

## 回退机制

```
任何 Spiral 中发现前置知识缺口：
  → 暂停当前 Spiral
  → 标注：[回退 · 补齐前置：{概念名}]
  → 用 teaching.md 的 Phase 1 Step 3（自适应补齐缺口）处理
  → 补齐后回到原位继续
```

## Guided/Unguided 切换规则

```
标记格式（每段输出开头必须标）：
  🎯 Guided — Bot 主动讲解
  🔧 Unguided — 用户动手，Bot 只给目标
  🔄 Hybrid — Bot 引导 + 用户同步操作

默认分配：
  Spiral 1 → 主要 🎯 Guided
  Spiral 2 → 主要 🔧 Unguided（卡点时切 🎯 Guided）
  Spiral 3 → 🔄 Hybrid（讲一段 → 用户实操验证 → 再讲）

切换信号（用户可随时触发）：
  "直接告诉我" → 切 🎯 Guided
  "我自己试" → 切 🔧 Unguided
  "一起做" → 切 🔄 Hybrid
```

## 做题协议的复用

当 Unguided 阶段涉及实际操作（安装、配置、调试）时，自动复用 problem-solving.md 的以下部分：
- 每步四部分输出（操作指令 / 验证检查点 / 失败预判 / 强制暂停）
- 卡住时的强制声明
- 硬性打断短句

不复用：事前验尸、CoVe 验证链（这些针对编程题/推理题，工具学习场景不需要）。
